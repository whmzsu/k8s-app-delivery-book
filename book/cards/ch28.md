## 一句话核心问题

**控制器写起来容易，怎么让它幂等、可测、可观测、可升级？**

## 结论（3 条）

| # | 结论 | 类型 | 计划引用（名称级） |
|---|---|---|---|
| 1 | Kubebuilder / controller-runtime 提供脚手架与协调循环；OLM 管理生命周期，但引入它也要承担依赖 | L1 | Kubebuilder Book；controller-runtime 文档；OLM 文档 |

## 反模式（3 条）

1. reconcile 里同步调用外部慢 API → worker 被占满、其他对象饿死 → 异步化 + 重入队列
2. 把中间状态写进 status → 重启后状态失真 → status 只表达观测结果
3. Operator 自身没有告警 → 它挂了业务静默降级 → 控制器健康指标与告警

## 验证与回滚

- **验证命令**：`make test`（envtest）；连续两次 apply 同一 CR 观察 `resourceVersion` 与副作用次数；`kubectl get <cr> -o yaml` 检查 status
- **通过标准**：重复事件无重复副作用；测试通过；控制器指标可查
- **回滚命令 / 步骤**：`helm rollback <operator-release> <rev>` 或 `kubectl apply -k operator/@<上一 tag>`；先删 CR 实例再降级控制器，检查 finalizer
- **回滚验证**：CR 实例无残留，业务 `verify.sh` 不受影响
