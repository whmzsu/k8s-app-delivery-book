## 一句话核心问题

**当工期、故障压力或历史包袱与原则冲突时，哪些可以谈，哪些一步都不能退？**

## 结论（4 条）

| # | 结论 | 类型 | 计划引用（名称级） |

| 1 | 产物必须一次构建、跨环境晋升；同一标签重复推送会让回滚失去确定的目标 | L1 | Kubernetes Images / ImagePullPolicy；Kubernetes Configuration Best Practices |

## 反模式（3 条）

1. 每个环境各构建一次「测试包」→ 生产跑的从没被测过 → 改为 build once / promote
2. 用 `latest` + `imagePullPolicy: Always` 图省事 → 节点间版本不一致、无法追溯 → 固定 SHA 标签
3. 「先上线，SLO 和告警下周补」→ 出事时没有判定标准 → 第 3 章给 1 页最小 SLO 卡片，第 20 章展开体系
