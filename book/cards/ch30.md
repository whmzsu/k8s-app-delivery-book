## 读者视角

- **读者带着什么问题来**：集群从 1 个变 5 个，发布、升级、集群供应全都得重来一遍，平台团队该提供什么？
- **学完你能……**：划清集群边界，用 IaC 与 GitOps 管理集群生命周期，并给出一条「有护栏的自助黄金路径」。
- **此刻 `order-demo` 长什么样 / 本章可验证动作**：双集群发布与黄金路径；一次变更同时发到两集群（`ch30-multicluster`）。

## 一句话核心问题

**团队与集群变多之后，前面的做法如何升级而不失控？**

## 反模式（3 条）

1. 为每个团队复制一套集群与流水线 → 升级与策略各自漂移 → 集中供应 + 标准化模板
2. 平台方把一切都包办并强制审批 → 研发排队、旁路滋生 → 护栏式抽象
3. `terraform apply` 在本地随手跑、state 在笔记本 → 状态不一致且无审计 → 远端 state + PR plan

## 验证与回滚

- **验证命令**：合并一个镜像 SHA 变更 PR；`argocd app list`（两集群各一份）；`terraform plan` 输出为空漂移
- **通过标准**：两集群同步成功；state 远端且无本地副本；黄金路径创建的新服务自带护栏
- **回滚命令 / 步骤**：`git revert <commit> && argocd app sync --prune`；集群供应侧回退 IaC 版本并按升级顺序逆向执行
- **回滚验证**：两集群 image 回到上一版 SHA，`verify.sh` 通过
