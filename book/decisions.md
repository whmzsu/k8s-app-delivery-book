## 一、未决项裁决

| 编号 | 事项 | 裁决 | 理由 |
|---|---|---|---|
| U-01 | 书名 | **《一次变更的旅程：Kubernetes 应用部署与管理运维最佳实践》**，封面/页眉简称《一次变更的旅程》 | 主标题对应全书主线「一次变更的旅程」，比《K8s 最佳实践》更能体现「决策书」定位；副标题保留检索关键词 |
| U-02 | 第 1 章事故形态 | **虚构合成案例**，正文显式标注「合成案例」 | 需要在同一时刻精确埋下 H1–H8 八个失效点，改编真实事故会受事实约束且涉及版权；L3 背书改用公开 postmortem 方法论，不把合成案例写成真实事件 |
| U-03 | 第 6 章是否讲「镜像怎么来的」 | **保留一小段（约 400 字，仅 Dockerfile + 一次构建 + SHA 标签）**，不讲 SBOM / 扫描 / 签名 | 读者要复现 `ch06-first-loop` 必须有镜像来源；供应链内容按 D-01 归第 24 章，不重复 |
| U-04 | 策略引擎统一值 | **Kyverno 1.x** 为唯一示例实现；**VAP（ValidatingAdmissionPolicy）** 作内置轻量方案对比；**Gatekeeper** 仅在选型矩阵出现 | 声明式策略好读、验签策略示例直观；CI 侧用同一策略库做静态校验，见第 25 章 |
| U-05 | 流量层统一实现 | **Gateway API + Envoy Gateway** 为唯一示例实现；**Istio** 仅在选型矩阵作对比；第 15 章渐进式交付用 Argo Rollouts 的 Gateway API traffic router 插件，**并给出「按副本比例金丝雀」作为不依赖流量插件的退化方案** | 避开服务网格的运维成本；插件属快速演进组件，必须同时给不依赖它的路径，防止示例随插件版本失效 |
