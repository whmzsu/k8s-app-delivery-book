# 速查手册图候选盘点（D-63 规划资产）

版本 `v0.1` · 2026-11-16 · 依据全书 31 章 + 附录 A–I 的实测扫描

## 这份文件是什么

盘点**书稿里哪些知识块适合做成「速查手册图片」**（一页纸 cheat sheet，读者可打印贴墙 / 存手机速查）。

这不是插图清单——插图是「讲清一个机制」，速查图是「在现场 30 秒内拿到结论」。两者目的不同，选取标准也不同：速查图优先选**结构化程度高、且读者会在关键时刻单独拿出来用**的块。

盘点基线（2026-11-16 实测，非记忆）：

| 事实 | 数据 |
|---|---|
| 现有矢量插图 | 13 个 SVG、14 处引用（`ch01-coordinate-system.svg` 被 ch01 与 ch31 复用） |
| 有插图的章 | 13 章：01、02、04、05、06（2 张）、08、09、14、17、20、24、26、31 |
| **零插图的章** | **18 章**：03、07、10、11、12、13、15、16、18、19、21、22、23、25、27、28、29、30 |

> **推论**：附录 G 是「结论索引」（每棵 5 行树），速查图应做「矩阵 / 时序 / 判据」层——**不要重复做树**，要做树给不出的东西。

## 判定标准

一个知识块值得做成速查图，需至少满足一条：

1. **多维对照表**：同一维度下 3+ 个并列选项，须横向比较才能理解（策略选型矩阵、信号 vs 症状）
2. **决策树 / 分叉路径**：读者到现场需「走到哪一步选哪条」才能行动
3. **时序 / 流程**：有明确先后顺序，**顺序错了会出事故**（探针时序、回滚步骤、证书轮换）
4. **反模式-症状-定位命令对照**：症状能直接映射到命令
5. **卡格式内容**：字段少、条目多，可当 checklist 用（SLO 卡片、runbook 卡片）
6. **一句话选型判据**：读者只想要结论、不想读论证

## 制作规范（建议，待定稿）

1. **命名**：`chNN-<slug>.svg`，与现有 13 张同规则；slug 用英文 kebab-case（如 `ch13-deploy-rollback.svg`）。
2. **尺寸**：首张卡实测采用 **A4 竖版**（`viewBox 0 0 1240 1680`，接近 1:√2）——7 行 × 4 带的信息量放在横版会挤到不可读；行数少的卡（如 SLO 卡片）可另考虑横版。正文内联的图保持现有纵向比例不变——**速查图是「附件」不是「插图」**，不进正文插图计数（否则第 9 步闸门与 README 插图数会失配）。打印建议 A4 精细打印或 A3 贴墙放大。
3. **放置**：两类候选落点——① 正文对应小节处内联一张**缩略版**（保证阅读连贯）；② 单独出「速查手册」页（附录 J 或独立 PDF），供打印。**建议以 ② 为主、① 为辅**：速查图的价值在于完整，缩略版放不下 7 行命令。
4. **可复制性**：命令列必须能被读者直接复制粘贴（用等宽字体，不做断行美化）——这是速查图与普通插图最大的区别。
5. **每图页脚**：章号 + 小节号 + 版本号（`VERSION`）+ 「详见第 N 章」跳转提示。
