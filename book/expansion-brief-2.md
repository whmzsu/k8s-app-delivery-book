# 终稿加深公约（第二轮，所有加深子代理共用）

版本 `v0.1` · 2026-11-11 · 运维专家统筹

## 背景
第一轮已按各章「终稿扩写清单」完成扩写，但部分章实际汉字仍低于章首「终稿目标 1.0–1.3 万字」。本轮任务是**在不注水的前提下把偏轻的章加深到目标量级**：只加有决策价值的内容，绝不为凑字数罗列 API 字段或重复已写段落。

## 动手前必读
1. `book/expansion-brief.md`（第一轮公约，铁律全部继续有效：不改章首固定块、不改配置契约、不改 references/*.yaml、不新建角标/URL、不提交 git、不写占位）。
2. `book/chapter-spec.md`（七段模板）。
3. 你负责的 `chapters/chNN.md`（**先通读，确认哪些决策还没写透，避免重复**）。
4. `references/chNN.yaml`（复用既有 `[R-NN-x]`）。

## 加深什么（按价值排序，优先前四类）
1. **更完整的失败现场**：给现有反模式补「一次可定位的复盘」——时间线、关键命令输出片段、误判与纠正。
2. **更硬的决策判据**：把「选 A 还是 B」补成可判定表——阈值、临界点、反例、适用前提。
3. **「何时不该用」案例**：每个主推做法补一个「不该用的具体情形」与代价。
4. **可执行配置的加深**：把已有 YAML 补成真正能跑全的版本（含边界字段、注释说明取舍），但不得改动冻结的配置契约值。
5. **跨章 worked example**：用 `order-demo` 把本章结论接到上下游章（如 ch04→14/30、ch08→13/15）。
6. **对照矩阵**：把二元对比扩成多维对照（成本/复杂度/适用规模/失败模式）。

## 不要做什么
- 不重复已写过的段落或结论；不加「综上所述」式空话；不堆 API 字段清单。
- 不改章首固定块、不改配置契约（命名空间/镜像 `:git-<sha7>`/端口/探针/资源基线/Secret 对象名 `order-demo-db-credentials`）。
- 不新增 `[R-NN-x]`/URL；缺背书的论断写成独立「本书观点」块。
- 不新增「回到第 1 章」段（2/3/8/9/13/14/22/23 章已有则保持）。
- 不提交 git，只编辑你负责的那一章。
