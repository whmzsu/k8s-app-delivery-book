# order-demo / gateway 可用性 SLO 契约

## 一、卡片字段（字段名与 ch03 `order-demo-slo-card` 逐字一致）
- service: gateway
- sli: 非 5xx 有效请求数 / 有效请求数
- window: 28d（滚动）
- objective: 99.9
- freeze_rule: 28 天剩余错误预算 <= 0 时冻结非必要发布

## 二、可测量定义（第 20 章正式口径）
- 有效请求：gateway Service 8080 上 route 不属于 /healthz /readyz /startup 的 HTTP 请求
- 成功请求：有效请求中 status_code 不属于 5.. 的请求
- 测量点：入口 gateway，指标 order_demo_http_requests_total（命名规范见第 21 章）
- 排除项：探针流量、发布窗口主动压测、演练注入
- 分母为 0 的处理：clamp_min 保护，分母为 0 时 SLI 记为 1，不产生坏事件

## 三、错误预算与窗口
- 错误预算 = 1 - 0.999 = 0.001（按 Occurrences 计）
- 快燃尽：1h / 5m 双窗 >= 14.4 → paging（第 22 章）
- 慢燃尽：6h >= 6 → ticket；3d >= 1 → 周会复盘
- 冻结判定：slo:order_demo_gateway:release_freeze == 1

## 四、冻结规则
- 冻结范围：功能发布、依赖升级、配置重构
- 豁免范围：回滚、安全补丁、止血变更（须登记例外）
- 例外审批：业务负责人 + 平台负责人双签
- 例外登记：编号 EXC-YYYYMMDD-NN、前提、补偿措施、到期时间（沿用第 3 章例外机制）
- 解除条件：剩余预算 > 0 且连续 3 个快窗口无燃尽告警

---

> 例外单六个必填字段（缺任一项即视为无效申请）：
> - `EXC-YYYYMMDD-NN`：编号，与 `docs/slo-contract.md` 表格、PR 标题三处一致；
> - **变更对象**：具体到 `git-<sha7>` 或 PR 号；
> - **前提**：为什么不能等到预算恢复（合同、监管、不可延期的外部事件）；
> - **影响面**：当前缺口与本次变更预计再消耗多少预算；
> - **补偿措施**：必须可验证——灰度比例、观察时长、限流阈值、回滚演练的时间戳，四者至少写三项；
> - **到期时间**：默认 ≤ 72 小时；安全补丁可放宽到 ≤ 7 天，但仍须写明补丁编号。
> 到期检查：`grep -E '^\| EXC-' docs/slo-contract.md | awk -F'|' -v today="$(date +%F)" '...'`（详见第 20 章）。
