# ADR 0004：教学用 CRD 的版本迁移路径（maintenancewindow）

- 状态：已接受（2026-11-10，仅教学样例；生产不适用）
- 问题域：第七篇演进轴，是否给扩展资源设计可迁移的版本线
- 候选：① 单版本 `v1` 直接落地 ② `v1alpha1 → v1beta1 → v1` 三段演进 + 转换 webhook
- 何时不该用：真实业务 CRD 上线前未规划迁移路径时；本 ADR 只服务第 27 章教学样例
- 选了什么：② `v1alpha1 → v1beta1 → v1` 三版本，配 conversion webhook（即 `spec.conversion.strategy: Webhook`）
- 不选的理由：
  - ① 单版本 `v1`：没有转换能力，旧实例无法升级、无法灰度，违反第 27 章 CL-27-03
    「明确写出版本迁移路径与转换 webhook 负责方式」的判据，直接上生产属反模式（AP-14 反面）
- 退出路径：教学结束按 27.5 顺序先删 CR 实例 → 确认 finalizer 清空 → 删 CRD → 卸载控制器
- 退出成本：低（仅教学资源，无业务数据）；对照第 5 章替换成本表为「高」的是真实 CRD
- 版本锁定：教学样例显式标注「仅教学」；真实 CRD 主版本见附录 A
- 复评周期：教学样例随第 27 章修订；真实 CRD 每次大版本升级复评一次
- 责任人：平台组（教学样例）／ 应用组（真实 CRD owner）
- 后果：正向——旧版本实例可无中断地升级到新 schema，升级与回退路径清晰；
  负向——多维护一份转换 webhook 与其部署，且 webhook 自身需高可用（第 26 章审计）。
