# 附录 E　术语表与概念梯度

> 本附录汇总全书术语的准确定义与出现位置（哪一章首次讲、讲到多深），是全书唯一术语真相源的可打印版。章内引用写「见第 X 章」，不写「上文 / 下一章」。

## E.1 核心术语

| 术语 | 本书定义 | 首次出现 | 正式定义章 | 禁用说法 / 常见误用 |
|---|---|---|---|---|
| 应用 application | 一组共同交付、共同回滚的工作负载与配置的最小单元，贯穿案例为 `order-demo` | 1 | 2 | 把「应用」等同于单个 Deployment 或单个 Pod |
| 环境 environment | 一套有独立凭据、独立配额、独立晋升入口的集群或命名空间集合；dev / staging / prod | 1 | 4 | 用「测试环境」泛指所有非生产；把命名空间当作完整隔离边界 |
| 构建 build | 由某个源码提交生成**唯一不可变制品**的过程，带 git SHA 标识 | 3 | 6、12 | 每个环境各构建一次；用 `latest` 标识产物 |
| 晋升 promote | 把**已构建的同一制品**逐级送到不同环境，只改配置不改产物 | 1 | 3 | 说成「重新打包发到生产」；把晋升与发布混用 |
| 发布 release / deploy | 让某个版本的制品在生产开始承载真实流量，并可按预案退出 | 1 | 13 | 把「推到仓库」「部署到集群」也叫发布 |
| 回滚 rollback | 把线上恢复到**上一个已知良好版本**；必须先有方案再有发布 | 1 | 13 | 说成「修一下再发一版」；与数据回退混为一谈 |
| 漂移 drift | 集群实际状态与 Git 声明状态不一致，多由手工变更或控制器副作用产生 | 1 | 14 | 只指配置被误改，漏掉手工 `kubectl edit` 与自愈副作用 |
| SLO | 对服务可靠性的量化承诺，由 SLI 与错误预算构成，是告警与发布冻结的依据 | 1 | 20 | 把「监控大盘」或可用性口号当 SLO |
| SLI | 可直接测量的好坏比例，如成功请求数 / 总请求数 | 3 | 20 | 用 CPU 使用率等业务无感指标充当 SLI |
| 错误预算 | 在一个窗口内允许不可用的额度；耗尽则冻结非必要发布 | 3 | 20 | 只写百分比不写窗口与冻结规则 |
| GitOps | Git 中声明期望状态，由控制器持续比对并收敛；Git 是唯一变更入口 | 1 | 14 | 把「用 Git 存 YAML」等同于 GitOps（缺持续收敛与漂移纠正） |
| 渐进式交付 | 按流量或请求比例逐步放量，用指标判定继续或自动回滚 | 13 | 15 | 与「灰度发布」随意互换而不说明判定依据 |
| 清单 manifests | 描述期望状态的 YAML/JSON 声明文件 | 2 | 10 | 把 `kubectl run` 之类命令式操作也叫清单 |
| 渲染产物 rendered manifests | 模板/overlay 渲染后、提交给集群前的最终清单 | 10 | 10、14 | 只 review 模板而不 review 渲染产物 |
| 不可变镜像 | 一旦推送不再修改，标签与内容一一对应 | 3 | 6 | 同一标签重复推送覆盖 |
| 工作负载 workload | 承载应用进程的 K8s 资源，如 Deployment / StatefulSet / Job | 2 | 7 | 直接创建裸 Pod 用于生产 |
| 控制循环 reconciliation | 控制器持续比对实际状态与期望状态并收敛 | 2 | 2、27 | 说成「K8s 自动帮你修好一切」 |
| CRD | 给 K8s 增加一种自定义资源类型 | 5 | 27 | 在定义前用它作为推理前提 |
| finalizer | 资源删除前的清理钩子，卡住会导致对象无法删除 | 16 | 27 | 只讲用法不讲卡住后的处置 |
| 准入策略 policy | 在资源进入集群前/时执行的校验或变更规则 | 11 | 25 | 把 CI 里的静态扫描也叫准入 |
| 金丝雀 canary | 把一小部分真实流量导向新版本，用指标判定继续放量还是回退 | 13 | 15 | 与「蓝绿」互换使用；只切流量、不设判定与回退路径 |
| 蓝绿 blue-green | 同时运行新旧两套完整副本，一次性切换流量入口 | 13 | 15 | 说成「也要按比例放量」；忽略双倍资源与数据双写的代价 |
| AnalysisTemplate | 渐进式交付中描述「用哪个查询、什么阈值判成败」的模板资源 | 13 | 15 | 与 `AnalysisRun` 混为一谈；阈值不留业务依据 |
| QoS 三档 | Guaranteed / Burstable / BestEffort，由 requests 与 limits 的关系决定驱逐顺序 | 17 | 17 | 认为「设了 requests 就是 Guaranteed」 |
| PriorityClass 与抢占 | 用优先级决定调度与驱逐顺序，高优先级 Pod 可抢占低优先级 Pod | 17 | 17 | 给所有工作负载都设高优先级，等于没有优先级 |
| Pod Security Standards | privileged / baseline / restricted 三档标准，按 warn / audit / enforce 三种模式生效 | 7 | 25 | 只开 warn 就认为「已经加固」 |
| Workload Identity | 让工作负载以云上身份直接换取短期凭据，替代长期静态密钥 | 26 | 26 | 与 ServiceAccount token 泛指混用；仍把长期密钥挂进 Secret |

## E.2 全书公理（不可协商项，第 1 章 1.5 首次亮相，第 3 章展开）

1. **build once, promote**：同一制品跨环境晋升，不为每个环境重新构建
2. **不可变镜像 + git SHA 标签**：禁用 `latest`
3. **配置与镜像分离**：环境差异只体现在配置，不体现在产物
4. **非 root 最小镜像**：默认以非 root 运行
5. **Git 为唯一真相**：生产变更只允许走 Git，禁止手工 `kubectl edit` 改生产
6. **回滚方案先行**：没有验证过的回滚方案，不允许发布
7. **SLO 先行于告警**：先有 SLO 与错误预算，再据此设计告警
8. **SSH 禁入生产**：排障走可观测与 runbook，不登机器
9. **密钥、Terraform state、`.env` 一律不入 Git**

> 第 8、9 条是第 1–7 条的衍生护栏（见第 3 章 3.2 的公理表）。若确需例外，必须写满附录 B.4 的「例外前提 + 补偿措施 + 例外有效期 + 审批与复盘」。

## E.4 书写格式约定（供校对与二次创作）

- K8s 资源名用代码格式并保持官方大小写：`Deployment`、`PodDisruptionBudget`、`topologySpreadConstraints`
- 工具首次出现带主版本（`Helm 4.x`），小版本只在附录 A 与配置文件里锁定
- 命令用行内代码；完整命令块必须可复制执行且带验证命令
- 引用来源只写 `[R-XX-N]` 角标，不写裸 URL；「本书观点」独立标注
- 数量与资源单位写「数值 + 单位」（`cpu: 100m`、`memory: 128Mi`）；成本只给相对比例与归因口径，不写具体单价
