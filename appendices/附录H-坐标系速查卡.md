# 附录 H　全书坐标系速查卡

> 第 1 章 1.3 提出，第 31 章用同一张图做首尾闭环。可单独打印，读书时放在手边；每章章首的「坐标标签」就是这张卡的坐标。

## H.1 一主线 + 两横切 + 一演进轴 + 地基篇

```
                    【地基篇 1–5】原则 / 边界 / 工具方法论（不占主线环节，撑住整条链）
                                  │
  定义 → 校验 → 打包 → 晋升 → 发布 → 运行 → 观测 → 响应      ← 一主线：一次变更的旅程
   6–9   11     10     14     13/15   17–19   20–21   22–23
                                  │
   ┌──────────── 横切 A：安全 · 策略 · 凭据（6 篇 24–26 汇总深化）────────────┐
   └──────────── 横切 B：可观测 · 可回滚 · 可审计（5 篇 20–23 汇总深化）─────┘
                                  │
   L0 手工 → L1 自动化 → L2 GitOps / 渐进式 → L3 平台化      ← 一演进轴
```

**为什么第 5、6 篇不按流水线顺序排**：它们是横切面，作用于主线的每一个环节，而不是链路上的某一段。把安全放到第 24–26 章是「汇总深化」，不是「最后才做安全」——每章检查清单固定含 2–3 条 `CL-S-xx` 安全项就是证据。

## H.3 成熟度阶梯

| 级别 | 特征 | 典型失效点 | 对应章 |
|---|---|---|---|
| L0 手工 | 手工 apply、凭经验排障、`latest` | 产物不可追溯、配置改了不生效 | 1–3 |
| L1 自动化 | SHA 标签、CI、清单校验、探针与回滚演练 | 多环境不一致、回滚没练过 | 6–13 |
| L2 GitOps / 渐进式 | Git 唯一真相、持续收敛、指标驱动放量、SLO 冻结 | 漂移、自愈误伤、告警无 runbook | 14–23 |
| L3 平台化 | 护栏内建、黄金路径、多集群、自助交付 | 抽象过度、Operator 无人维护 | 27–31 |

## H.4 章首坐标标签怎么读

格式：`位置：<主线环节/地基/横切/演进轴> ｜ 横切：<A/B/无> ｜ 成熟度 <L0–L3>`

- **横切 A**＝安全、策略、凭据；**横切 B**＝可观测、可回滚、可审计
- 示例：`位置：主线 · 发布 ｜ 横切：B 可回滚 ｜ 成熟度 L1`（第 13 章）
- 每章开头还有固定块「此刻 `order-demo` 长什么样 / 本章可验证动作 / 复现 tag」，来自附录 D

## H.7 全书符号约定（一行一符号）

本书用到十二种编号与标记。**先看这张表，再往下读**——它们都是「指路牌」，不是要背的知识点；遇到不认识的符号，回来查这一页比翻正文快。

| 符号 | 形态 | 含义 | 出现位置 | 去哪查全 |
|---|---|---|---|---|
| 事故钩子 | `H1`–`H8` | 第 1 章 8 个失效点，全书埋线 | 章首坐标标签、8 个主责章章末「回到第 1 章」 | H.5 表；第 31 章逐条重演 |
| 引用角标 | `[R-NN-x]` | `NN`＝章号，`x`＝该章序号 | 正文句末；不写裸 URL | 章末第 7 段（元信息）→ 附录 I（链接与归档） |
| 来源分级 | `L1` `L2` `L3` | L1 规范官方 / L2 权威著作 / L3 案例实证 | **只跟在 `[R-]` 条目里**，写成「L1｜标题｜机构…」 | 1.6 引用说明；附录 I |
| 章内检查项 | `CL-NN-xx` | `NN`＝章号，本章专有检查项 | 该章 §N.6 四列表 | 附录 B 汇总索引 |
| 安全项 | `CL-S-xx` | 每章固定 2–3 条的横切安全项 | 各章 §N.6 混排 | 附录 B 安全项池 |
| 通用项 | `CL-G-xx` | 与章节无关的母版项（产物、配置、观测…） | 各章 §N.6 引用，不重复展开 | 附录 B.1 母版 |
| 成熟度 | `L0`–`L3` | L0 手工 → L1 自动化 → L2 GitOps → L3 平台化 | 章首坐标标签、H.3 表 | H.3；31.6 路线图 |
| 反模式 | `AP-xx` | 全书 30 条反模式编号 | 第 31 章三张表（总表 / 识别 / 处置） | 第 31 章；`docs/antipatterns.md` |
| 例外登记 | `EXC-YYYYMMDD-NN` | 明知违规的临时许可，带前提与到期时间 | 例外机制相关章节与模板 | 第 3 章；`docs/policy-exception.md` |
| 复盘改进项 | `ACT-xx` | 复盘产出的动作项编号 | 第 23 章复盘模板 | 附录 C 复盘模板 |
| 示例 tag | `chNN-<名>` | 该章对应的可 checkout 代码状态 | 章首固定块「复现 tag」 | 附录 D；`book/case-evolution.md` |
| 节引用 | `§N.x` | 第 N 章第 x 节 | 全书交叉引用 | — |

**三组最容易混的，记这一句就够**：

1. **`L1`–`L3` 有两个含义**，靠「跟不跟 `[R-]`」区分。**跟在引用条目里**（`[R-21-3] L1｜…`）＝来源分级，证明「这话有出处」；**跟在章首或路线图里**（`成熟度 L2`）＝你的团队处在哪一级。成熟度有 `L0`，来源分级没有 `L0`——这是最快的辨识法。
2. **`CL-` 有三种前缀**，靠「后面跟什么」区分。`CL-08-03` 是第 8 章自己的检查项；`CL-S-` 是安全项（S = Security）；`CL-G-` 是通用项（G = General），引自附录 B 母版，各章不再重写。
3. **`AP-` 是「错的写法」，`ACT-` 是「事后要做的事」**。前者在第 31 章有完整表，后者只在复盘模板里出现，两者编号独立、不互相引用。

> **为什么保留这些编号**：它们不是装饰。`[R-]` 让「这句话有出处」可被第三方复核，`CL-` 让「上线前该查什么」可被逐条签字，`AP-` 让「同一个坑犯过几次」可被计数。去掉编号，这三件事就退化回「作者说的」和「大家注意一下」。代价是你得记住十来种前缀——所以才有这一页。

## H.8 统一章节模板（七段）

`N.1 问题与反模式` → `N.2 范式与决策树` → `N.3 工具选型` → `N.4 落地配置` → `N.5 验证与回滚` → `N.6 上线检查清单` → `N.7 依据与延伸阅读`（之后按需写「回到第 1 章」）。横切章 24–26 精简为三段 + 依据段；专题章 1、23、31 按叙事组织。第 7 段的 `[R-XX-N]` 角标与附录 I 一一对应；「本书观点」独立标注，不混进背书列表。

## H.9 排版与复制约定（命令以显示文本为准）

PDF、EPUB、DOCX 与 GitHub 网页都由同一份 Markdown 装配。为了让宽表格排得进版心，源码与成品在**管道符**上有两处必然差异，先讲清楚，免得照抄源码时命令反而失效。

1. **表格里的 `\|` 会显示成 `|`**。这是表格语法的规定：先按管道切单元格，被转义的 `\|` 再还原成字面管道。检查清单「怎么查」列里，shell 管道（`-o yaml | grep ...`）与正则分支（`'good|total'`）在源码中都写作 `\|`，成品中都显示为 `|`。这不是排版错误，**也不要在成品里把反斜杠补回去**。
2. **命令以成品里显示的文本为准**。本书检查清单的正则分支统一用扩展正则，写成 `grep -nE 'good|total'`，照 PDF / 网页上的样子复制即可执行。若从仓库 `.md` 原始文本复制，会带上表格转义用的反斜杠（`grep -nE 'good\|total'`），在扩展正则下反而退化成字面匹配——不要这样复制。
3. **代码块里的 `\|` 是正则语法，不是转义**。代码块不经过表格切列，反斜杠是故意保留的：`grep 'password\|token'` 是基本正则（BRE）的「或」。不要删掉反斜杠，也不要给它加 `-E`。
4. **完整可复制的配置与脚本在仓库里**。`examples/order-demo/` 是第 6 章基线；`examples/by-chapter/` 由 `hack/materialize.py` 从章内代码块自动生成，用 `python hack/materialize.py --check` 可逐文件核对。印刷版本来就复制不了，所以书内保证「照着敲能跑」，仓库保证「复制就能跑」。
5. **版面折行不是命令的一部分**。长命令为适应版心可能换行显示，誊录时按同一行拼接，中间不插空格或续行符。EPUB 在窄屏上宽表格会横向滚动，可切横屏阅读，或到 `examples/` 找同名文件。
6. **字面值不因排版改变**。正文里的 `git-<sha7>` 镜像标签、`order-demo-{env}` 命名空间都是要逐字照抄的字面约定，不是「换成你自己的值」的占位示例；版本基线以附录 A 为准。

> **一句话**：表格里的命令看成品，代码块里的命令看原文；要真正执行，去 `examples/` 拿文件。
