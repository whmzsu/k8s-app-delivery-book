# 附录 B　上线前检查清单（可打印）

> 由 `book/checklist-master.md` 母版 + 31 章专有项汇总生成。质量规则：每条必须写清**怎么查 / 通过标准 / 失败处置**。使用时按「发布前 24 小时 → 发布中 → 发布后 30 分钟」三段逐条打勾；任何「失败处置」指向「禁止发布」的项未通过，即中止发布。各章专有项 `CL-NN-xx` 见对应章 §N.6。

## B.1 通用上线检查项（母版）

### 产物与版本

| 编号 | 检查项 | 怎么查 | 通过标准 | 失败处置 |
|---|---|---|---|---|
| CL-G-01 | 镜像标签为 git SHA | `kubectl get deploy -o jsonpath='{..image}'` | 全部为 `git-<sha7>`，无 `latest` | **阻断发布**，回见第 6、12 章重建晋升 |
| CL-G-02 | 各环境产物一致 | 对比 dev/staging/prod 的 image 字段 | 完全相同，仅配置不同 | 回见第 3 章查是否为环境重新构建 |
| CL-G-03 | 渲染产物已 review | 保存 `helm template` / `kustomize build` 输出并 diff | 与上一版 diff 只包含预期变更 | 回见第 10、14 章 |

## B.3 发布三段式执行卡

**发布前 24 小时**：CL-G-01/02/03、CL-G-04/05/06、CL-G-07、CL-G-09、CL-G-10、CL-S-01/02/03。任何一项失败 → 中止，按「失败处置」回对应章。

**发布中**：CL-G-08（容量账）、CL-G-12（验证命令已就绪）、CL-S-04（无手工通道）；记录每一步的开始/结束时间与执行人，写入发布记录（Git PR 描述即可）。

**发布后 30 分钟**：跑章内「验证命令」与「通过标准」；查 SLO 消耗速率与告警触发；确认回滚命令仍可执行（`rollout history` 未被清理）。若出现「症状 → 定位 → 处置」速查表里的任一症状，立即按附录 C 的 runbook 止血，不在发布现场做根因分析。

## B.4 例外登记模板

公理不可协商；若确需例外，必须写满四项并留痕，否则视为违规：

```
例外编号：EX-<日期>-<序号>
例外前提：<为什么这次可以不符合该公理>
补偿措施：<同期生效的额外护栏，必须可验证>
例外有效期：<到哪个时间点自动失效>
审批与复盘：<谁批准、何时复盘、复盘结论写在哪>
```

> 典型例子：紧急止血时临时改生产清单，必须同时登记「何时回写 Git」「谁负责漂移纠正」「多久内关闭例外」，见第 14、23、26 章。
