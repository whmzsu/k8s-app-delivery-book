# 附录 J　速查手册页

> 可单独打印，也可存进手机相册。这里给出**统一版式**和**五张卡的一次性排布**；每张卡的成品 SVG 随仓库附件提供，路径见 J.3。本附录是「索引 + 卡面规格」，不是把图塞进正文。

## J.1 与其他「速查」资产的分工

本书有四张名字里都带「速查 / 卡」的资产，回答的问题完全不同。混用会让读者在事故现场翻错地方：

| 资产 | 回答的问题 | 形态 | 读者时刻 |
|---|---|---|---|
| 附录 F　工具全景速查表 | 这一层有哪些工具可选 | 表格 | 选型前，坐着查 |
| 附录 G　选型决策树合集 | 走到这个岔路口该选哪条 | 7 棵 5 行树 | 评审会上，结论索引 |
| 附录 H　坐标系速查卡 | 我现在在全书哪个位置 | 一张坐标图 | 读书时，手边参照 |
| **附录 J　速查手册页（本附录）** | **现场 30 秒拿到一条能敲的命令** | **5 张图（附件）** | **出事 / 发布 / 演练时，单独拿出来** |

**一句话区分**：附录 G 给「选哪条」，本附录给「敲什么」。树不写命令，图不铺论证。

## J.2 统一版式规范（五张卡共用）

### J.2.1 尺寸与区块顺序

- **尺寸**：A4 竖版，`viewBox="0 0 1240 1680"`（接近 1:√2）。行数少的卡（如单卡片式 SLO 卡）可改横版，但同一批内保持一致。
- **区块顺序固定**：页眉 → 现场动作条（五步法 / 判定顺序）→ 数据行 → 共性与关卡 → 页脚。**不允许为塞内容删掉页眉或页脚**——那是读者判断「这张卡属于哪一章、哪个版本」的唯一依据。
- **数据行结构**：每张卡 5–7 行，每行 4 带：对象名 → 一眼判据 → 定位/执行命令 → 首步动作。行高 170，带高 46 / 52 / 50。

### J.2.2 颜色语义（与正文插图同一套色板）

| 语义 | 底色 / 描边 | 文字色 | 用在哪 |
|---|---|---|---|
| 一眼判据 | `#fffbeb` / `#fde68a` | `#78350f` | 动手前必须念出的那句话 |
| 命令（只读 / 可执行） | `#f8fafc` / `#e2e8f0` | `#1e293b` | 等宽命令列 |
| 止血 / 首步动作 | `#fef2f2` / `#fecaca` | `#7f1d1d` | 会改变集群状态的动作 |
| 现场动作条 | `#f0f9ff` / `#bae6fd` | `#0369a1` | 五步法、判定顺序 |
| 共性与关卡 | `#f5f3ff` / `#c4b5fd` | `#4c1d95` | 卡尾的共性、口头关卡 |
| 页眉 / 页脚 | `#1e293b` / `#94a3b8` | `#ffffff` / `#94a3b8` | 章号、小节号、版本 |

颜色不是装饰：**红底 = 会改状态，琥珀底 = 判据，灰底 = 只读命令**。读者扫颜色就知道这条命令能不能直接敲。

### J.2.3 字体与可复制性

- 正文：`'Microsoft YaHei','PingFang SC','Noto Sans CJK SC',sans-serif`（与正文 SVG 插图同一字体栈；CI 上由 `fonts-noto-cjk` 兜底）。
- 命令：`'Cascadia Mono','Consolas','DejaVu Sans Mono',monospace`。
- **命令单行不折行，不做断行美化**——折成两个 `<text>` 会让复制时混入换行，贴进终端就执行不了。这是速查图与普通插图最大的区别。
- 占位符（`<pod>`、`<namespace>`、`<上一版>` 等）在页眉统一说明，不在命令里重复解释。

### J.2.4 页脚与版本

每图页脚固定四件：**章号 + 小节号 + `VERSION` 版本 + 「详见第 N 章」**，末尾标注「速查附件 · 不进正文插图计数」。版本随根目录 `VERSION` 同步；发版时若版本号变了，五张卡页脚都要改。

### J.2.5 放置与计数

- 成品落在 `book/cards/cheatsheets/chNN-<slug>.svg`，与章卡片 md 同目录树、不同资产类型。
- **不进正文插图计数**：这些 SVG 不被任何 Markdown 插图语法引用（感叹号 + 方括号 + 圆括号那种写法），因此九步闸门第 9 步的「README 声明插图数 == 全书 SVG 引用数」不受影响。附录 J 本身也只用路径文本引用，不写插图语法——连「作为反例说明」都不能写出那个语法，闸门的纯文本正则不看反引号。
- 盘点、状态与防重复规则见 `book/cheatsheet-inventory.md`；资产登记见 `book/cards/INDEX.md`。

## J.9 维护与校验

新增或更新一张速查图的顺序固定：

1. **先改盘点**：在 `book/cheatsheet-inventory.md` 的候选表确认它与 Top 5 已有卡不重叠，写清「读者时刻」；
2. **再出图**：按 J.2 版式做 `chNN-<slug>.svg`，落 `book/cards/cheatsheets/`；
3. **三项校验**：先跑 `python hack/check-cheatsheet.py book/cards/cheatsheets/*.svg`（一次校验全部：XML 合法、A4 竖版 viewBox、文本左右边界、页眉章号与页脚 `VERSION` 同步）→ Edge/Chromium headless 实渲染目视确认（无截断、无重叠、命令等宽可读）；
4. **回填状态**：更新 J.3 总览表的「状态」与「成品文件」列，并登记 `book/cards/INDEX.md`；
5. **发版同步**：若 `VERSION` 变了，五张卡页脚的版本号一起改。

**边界**：速查图只保证「现场 30 秒拿到可执行结论」，不替代正文的论证与反例，也不替代人工版式审阅。它不进正文插图计数、不参与四格式装配——读者拿到的是仓库附件，不是 PDF 里的一页。
